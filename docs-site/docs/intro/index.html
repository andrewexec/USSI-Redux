Getting Started

USSI Redux is a saveinstance for Roblox executors, written in Luau. It revives the saveinstance function from Synapse X and can also be edited and used as a Roblox-format-file writer.

Load it​

local Params = {
	RepoURL = "https://raw.githubusercontent.com/andrewexec/USSI-Redux/main/",
	SSI = "saveinstance",
}

local synsaveinstance = loadstring(game:HttpGet(Params.RepoURL .. Params.SSI .. ".luau", true), Params.SSI)()

synsaveinstance({}) -- saves with the default options

Pass a table of options to change what is saved and how:

synsaveinstance({
	mode = "full",
	SafeMode = true,
	DecompileTimeout = 15,
})

Option names are not case-sensitive, and many have aliases. Every option is listed on the API Reference page, and the generated type page documents the SaveInstanceOptions type.

Output​

By default the save is a binary place file (.rbxl, or .rbxm for a model). It is much smaller and faster to load than XML. Set XML = true for .rbxlx / .rbxmx.

OptionDefaultMeaning
BinarytrueSave as binary instead of XML.
CompressionMode"zstd"How binary chunks are compressed: "zstd", "lz4" or false for none.
CompressionLevel9Compression strength from -7 to 22. Higher is smaller but slower.
CallbackfalseSend the data to a function instead of writing a file.
CopyToClipboardfalsePut the output on the clipboard. Only suits small saves.
MaxDepth1000Objects nested deeper than this are moved up under their ancestor at that depth, so nothing is dropped. This stops very deep hierarchies from overflowing the stack when Roblox Studio opens the file.

Modes​

mode chooses what gets saved.

ModeWhat it saves
"optimized" (default)The most important services: Workspace, Players, Lighting, ReplicatedStorage, StarterGui and others.
"full"Everything under game. It also sets IgnoreDefaultProperties to false, unless you set that option yourself.
"scripts"Only the objects that are, or contain, a script, plus the parents that lead to them.
any other valueOnly ExtraInstances (and Object, if set).

If you set Object, "optimized" becomes "full". Saving game as the Object is the same as "full".

IgnoreDefaultProperties only affects XML output. Binary saves do not use it.

-- keep every property
synsaveinstance({ mode = "full" })

-- "full" mode, but still skip default values
synsaveinstance({ mode = "full", IgnoreDefaultProperties = true })

Decompiling scripts​

Scripts are decompiled automatically. saveinstance uses your executor's decompile, and falls back to MoonDecompiler, a decompiler written in Luau that is downloaded from this repository the first time it is needed. The fallback is used when the executor has no decompile, it errors, or it returns nothing.

OptionDefaultMeaning
DecompiletrueTurn decompiling on or off.
Decompiler"auto""auto", "executor" (only the executor's decompiler) or "moon" (only MoonDecompiler).
CustomDecompilerfalseYour own decompiler: a function (script, bytecode) -> string, or a table with a decompile method. It is tried first.
DecompileTimeout10Seconds one decompile call may take. -1 disables the timeout.
DecompileThreads1How many scripts to decompile at once. Only helps if your executor's decompile yields.
scriptcachetrueReuse decompiled output for identical scripts.
SaveBytecodefalseAdd each script's bytecode to its Source as a comment.
synsaveinstance({
	CustomDecompiler = function(script, bytecode)
		return decompileWithMedal(bytecode) -- return the source text
	end,
})

Functions MoonDecompiler can't rebuild with normal structure are saved as a loop, or as a commented disassembly, and start with a comment saying why.

Recovering from a crash​

Some executors crash on particular scripts during decompile. USSI Redux remembers which script was being decompiled, so you can run the save again.

  1. Before each decompile, the script is recorded in EXEC_STATE.json. The record is removed when the decompile finishes.
  2. If the executor crashes, the record is still there on the next run. That script is marked as crashed.
  3. The next run skips it. Its Source says it crashed the executor on a previous run, and the rest of the save carries on.
OptionDefaultMeaning
SkipCrashedScriptstrueTurn this protection on or off. It needs writefile.
RetryCrashedScriptsfalseForget the remembered scripts and try them again.

Closing the game in the middle of a decompile looks the same as a crash, so that script is skipped on the next run. If a script was skipped by mistake, run once with RetryCrashedScripts = true.

The same state file remembers which gethiddenproperty types crashed or failed on your executor, so those types are skipped on later runs.

Staying safe​

OptionDefaultMeaning
SafeModefalseDisconnects you from the game when saving starts, and turns on KillAllScripts and BoostFPS unless you set them. Highly recommended.
KillAllScriptsfalseKills all scripts to protect you further. SafeMode also turns it on.
BoostFPSfalseTurns off 3D rendering while saving. SafeMode also turns it on.
AnonymousfalseRisky. Removes your name and user ID from the file.
IgnoreSpecialPropertiesfalseDon't use gethiddenproperty. Helps if your executor crashes or the file is corrupted.
SaveSpecialPropertiesfalseSave only the special properties you list, for example {"Color3uint8"}. An empty list skips them all.

saveinstance does not modify game state.

Using the options type​

saveinstance.luau is written for Luau's --!strict mode and exports a SaveInstanceOptions type. If you type-check your own scripts, you can use it to get autocomplete and errors for misspelled options:

local options: SaveInstanceOptions = {
	mode = "full",
	DecompileTimeout = 15,
}
